# Results

Plugin v2.6.0-rc1 on lab v0.2.0, fourteen cells, -j 4 with a 60 s stagger, 2026-10-11.

Totals (eleven cells with verdicts, 2667 rows): 1030 PASS, 781 N/A, 264 FAIL, 592 BLOCKED. Three cells (kea-relay, chr, openwrt) wrote no verdicts: kea-relay stopped at its relay probe (no relayed ACK reached the client observer, a lab error, so no shape ran), chr and openwrt on a missing base-image prerequisite on the lab host. Capture hygiene was not tallied for this run.

Read the FAIL and BLOCKED rows with two things in mind. First, every cell exited with an infrastructure error (rc 1), so a row reading BLOCKED mostly means the cell lost its docker host or source over ssh under load, not that the plugin misbehaved. Second, the D3, D4 and F scenario rows are missing for the same reason: the lab aborted each shape at scenario D2b (the IPv6 SLAAC no-RA check) because it tried to write an empty capture as a PASS's evidence. That is a defect in the lab's verdict writer, not in the plugin.

Plugin finding: 38 verdicts fail with CreateEndpoint hitting its client timeout while awaiting headers. The dnsmasq and host-ubuntu2404-isc-dhcp cells, which were mostly BLOCKED, were rerun alone, and the first rerun verdicts were PASS, so the BLOCKED rows the reruns turned into PASS are the lab's. The ipvlan, bridge-ipam and macvlan-ipam BLOCKED rows of host-ubuntu2404-isc-dhcp are not among them: they came from a plugin link left over from the macvlan shape (old plugin behaviour), not from the lab. The rerun verdicts are not part of the totals or the tarball of this page.
