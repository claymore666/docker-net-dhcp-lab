# Results

Plugin v2.7.0 (installed by its signature-verified digest) on lab dev 2c3e925, against a home Fritz.Box. One cell, `fritzbox-home`: the router's own DHCP server, and a Debian 13 Docker host (docker 26.1.5) on its LAN. Two shapes, macvlan and macvlan-ipam; bridge and ipvlan are not run on a home router. 2026-10-31, about 20 minutes.

The run is limited to 18 scenarios that do not disturb the home network: six fixed MAC addresses, no router login and no router setting changed, no IPv6 (the home LAN has none), nothing that restarts the Docker host or its engine. Every other row on the page is N/A, and its verdict file says why.

Totals (one cell, 136 rows): 31 PASS, 3 FAIL, 102 N/A, 0 BLOCKED. A12 (network disconnect and reconnect) was in the list and is N/A on both shapes: docker 26 does not carry a MAC on `docker network connect` of a running container, so the reconnect would lease under a MAC outside the six.

The three FAIL rows:

- B3 (DNS registration), both shapes: with `register_dns=true` the box's DNS did not answer the container's hostname within 30 s. On the wire, the first DISCOVER and REQUEST carried neither option 12 (host name) nor option 81 (client FQDN). One later REQUEST carried option 81 with the hostname and no option 12. The plugin's reference says option 81 reuses the hostname already sent as option 12, which this capture does not show. Whether the box would register a name sent as option 81 alone was not measured.
- B7 (lease release), macvlan-ipam: a lab artifact, not a plugin finding. The RELEASE was on the wire on both shapes. The check then asks the box to offer the released address to a second MAC; that MAC had been offered another address in the macvlan run just before, and the box offered it that address again (RFC 2131 4.3.1 lets a server prefer a client's earlier address). The macvlan row, where the second MAC was still new, is PASS.

A first run on the same day stopped at A3 (compose down/up) after A1 and A2 passed: compose 2.26.1 on this engine drops a service-level `mac_address`, so the container would have come up under a MAC outside the six. The run aborted before it leased, and its cleanup came back clean. The compose file now sets the MAC under the network; this page is the second run.

Cleanup after the run: no lab container, network, plugin, image or plugin state left; no lab link on the host; the host's address and default route unchanged; every address the box acknowledged has a RELEASE on the wire after its last ACK. Whether the box offers each address to another client again could not be measured: the box keeps a device entry per MAC and offers each MAC the address it had before, so the check cannot tell a held lease from a pinned one. The router owner removes the six device entries by hand.
