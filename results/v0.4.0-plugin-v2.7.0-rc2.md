# Results

Plugin v2.7.0-rc2 on lab dev 67c28eb (v0.3.0 plus the #121 fix, #122). This run repeats the cells the previous run ([plugin v2.7.0-rc1 on lab v0.3.0](v0.4.0-plugin-v2.7.0-rc1.md)) could not run, plus pihole. The terms are the same as on that page: a cell is one DHCP source and one Docker host, both virtual machines; a shape is the way the plugin attaches a container to the source's network (bridge, ipvlan, macvlan, and the IPAM shapes bridge-ipam and macvlan-ipam, where Docker hands out the addresses and the plugin does not lease); a scenario is one measured step, and its verdict is PASS, FAIL, BLOCKED (a step before the measurement failed) or N/A (does not apply to that shape or source).

Eight cells, -j 3 with a 60 s stagger, 2026-10-30. Wall time 12 h 29 min; peak host load 15.9. It started while the previous run's last three cells were still going, so for the first three and a half hours the host carried both runs.

Totals (eight cells, 2680 rows): 1272 PASS, 890 N/A, 160 FAIL, 358 BLOCKED. Docker hosts: Debian 13 with docker 29.9.2 (kea, kea-ha, kea-relay, dnsmasq, pihole), Ubuntu 24.04 with docker 29.9.2 (the two host-ubuntu2404 cells) and Debian 11 with docker 20.10.24, the plugin's oldest supported engine (host-debian11-docker2010: 209 PASS, 8 FAIL, 5 BLOCKED, every non-PASS row in a group below, nothing engine-specific). Each cell's retry pass is part of its result: a first-attempt FAIL whose cause was a CreateEndpoint call (Docker asking the plugin for the container's address) running into the engine's client timeout is re-run once at the end of the cell; the table shows the rerun, the first attempt is kept under `evidence/<cell>/retried/`. 13 rows were re-run (kea-relay 6, dnsmasq 2, kea 2, kea-ha 1, host-ubuntu2404 1, host-debian11-docker2010 1), all PASS.

Plugin findings:

- Behind a relay the plugin does not renew at T1 (kea-relay, 16 rows): C12b 5 FAIL and C2 5 FAIL on every shape, E1/E2 6 BLOCKED on bridge, ipvlan and macvlan. A client renews its lease halfway through (T1) by unicast to the server; when the lease came through a relay the plugin sends nothing at T1 and renews only at T2 (REBIND, broadcast). The lease is kept, so the container stays reachable. Plugin #1419 (v2.8.0), library dhcp-golib #94 (fixed there). Not a regression: no earlier page has a kea-relay row past the relay probe.
- D4b (prefix withdrawn): PASS on every shape where the row ran (bridge and macvlan on dnsmasq, host-ubuntu2404, host-ubuntu2404-dnsmasq and host-debian11-docker2010; kea bridge), the #1412 fix in rc2. The remaining D4b rows are in the teardown and environment groups.
- B7 (lease release), C6b (late squatter), D2 (SLAAC), the D3 rows (IPv6 mode auto) and F7-pref64: PASS on every shape where they ran; every other row of theirs is in the teardown and environment groups, except pihole ipvlan C6b (#132, above).
